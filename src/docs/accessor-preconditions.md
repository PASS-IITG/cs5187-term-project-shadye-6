# fastgltf v0.9.1 Accessor Preconditions & API Contract

This document formalizes the public API contract for fastgltf's accessor tools in `include/fastgltf/tools.hpp`. It defines the boundary between **documented precondition violations** (which are harness bugs) and **target vulnerability candidates**.

---

## 1. Accessor Tools Public Contract

fastgltf provides templated tools for reading and iterating accessor data:
- `getAccessorElement<ElementType>(asset, accessor, index, adapter)`
- `iterateAccessor<ElementType>(asset, accessor, adapter)`
- `iterateAccessor<ElementType>(asset, accessor, functor, adapter)`
- `iterateAccessorWithIndex<ElementType>(asset, accessor, functor, adapter)`
- `copyFromAccessor<ElementType>(asset, accessor, dest, adapter)`

### Documented Preconditions

1. **`ElementType` Compatibility**:
   Every accessor tool asserts that `accessor.type == ElementTraits<ElementType>::type`:
   ```cpp
   assert(accessor.type == Traits::type && "The destination type needs to have the same AccessorType as the accessor.");
   ```
   Calling an accessor tool with an `ElementType` whose `AccessorType` differs from `accessor.type` triggers an assertion failure.

2. **Supported `ElementTraits` Mapping**:
   | AccessorType | Supported `ElementType` | Component Types |
   | :--- | :--- | :--- |
   | `Scalar` | `int8_t`, `uint8_t`, `int16_t`, `uint16_t`, `int32_t`, `uint32_t`, `float`, `double` | 5120, 5121, 5122, 5123, 5124, 5125, 5126, 5130 |
   | `Vec2` | `fastgltf::math::fvec2` | Float |
   | `Vec3` | `fastgltf::math::fvec3` | Float |
   | `Vec4` | `fastgltf::math::fvec4` | Float |
   | `Mat2` | `fastgltf::math::fmat2x2` | Float |
   | `Mat3` | `fastgltf::math::fmat3x3` | Float |
   | `Mat4` | `fastgltf::math::fmat4x4` | Float |

3. **Buffer View Index Validity**:
   - If `accessor.bufferViewIndex` is `std::nullopt`, fastgltf initializes elements with zeros (or sparse values if sparse is defined).
   - If `accessor.bufferViewIndex` is present, it must be `< asset.bufferViews.size()`.

4. **Sparse Accessors**:
   - Sparse index count is `accessor.sparse->count`.
   - `indicesBufferView` and `valuesBufferView` must point to valid bufferViews.
   - Indices must be scalar integers (`Byte`, `UnsignedByte`, `Short`, `UnsignedShort`, `Int`, `UnsignedInt`).

## 2. Classification Rules

### `HARNESS_BUG`
Any crash or assert failure caused by:
- Instantiating a template with an `ElementType` incompatible with `accessor.type` (e.g. calling `getAccessorElement<fvec3>` on a `Scalar` accessor).
- Passing out-of-range indices generated by harness logic.
- Passing an unallocated destination buffer to `copyFromAccessor`.

### `TARGET_CANDIDATE`
Any crash, sanitizer report, assertion failure, or unhandled exception when:
- The input was returned by `Parser::loadGltf(...)` without returning an error.
- The harness correctly dispatches according to `accessor.type` and `accessor.componentType`.
- The target attempts out-of-bounds byte reads within `DefaultBufferDataAdapter` or `deserializeComponent`.
- The target encounters arithmetic overflow in stride / offset calculation.

---

## 3. Independent Extent Calculation

For any accessor with an associated `bufferView`, the required byte extent is computed by checked arithmetic:
$$\text{requiredExtent} = \text{byteOffset} + \text{stride} \times (\text{count} - 1) + \text{elementSize}$$
where $\text{stride} = \text{bufferView.byteStride} \mathbin{\text{or}} \text{elementSize}$.

If $\text{requiredExtent} > \text{bufferView.byteLength}$, the asset contains an out-of-bounds accessor definition. If `Parser::loadGltf` accepts this input without error and subsequent tool access performs an out-of-bounds memory dereference, this represents a target memory safety finding.
