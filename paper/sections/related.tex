\section{Related Work}
\label{sec:related}

\paragraph{Structure-Aware and Grammar Fuzzing.}
Coverage-guided fuzzers such as libFuzzer~\cite{serebryany2016libfuzzer} and AFL++~\cite{fioraldi2020aflplusplus} support custom mutators for complex formats, and engines like NAUTILUS~\cite{aschermann2019nautilus} generate grammar-valid inputs.
We share their goal of maintaining structural validity to reach deep code paths.
However, prior grammar fuzzers target file parsers; \tool extends structure-aware mutation to multimedia rendering and network streams via headless in-memory shims.

\paragraph{Adaptive Mutation and Bandit Scheduling.}
Adaptive fuzzers dynamically allocate mutation energy: AFLFast~\cite{bohme2016aflfast} models seed transitions via Markov chains, Woo et~al.~\cite{woo2013scheduling} formulated operator scheduling as a bandit problem, MOpt~\cite{lyu2019mopt} uses particle swarms, and EcoFuzz~\cite{yue2020ecofuzz} applies adversarial bandits.
We share their goal of optimizing mutation operator payoffs.
We differ by implementing Discounted-UCB~\cite{garivier2011nonstationary} for non-stationary feedback and decoupling coverage accounting via GNU linker wrapping (\texttt{-Wl,--wrap}) to intercept edge rewards independently without colliding with libFuzzer.

\paragraph{Network and Protocol Fuzzing.}
Stateful network fuzzers like AFLNet~\cite{pham2020aflnet} send packets over OS sockets, while snapshot tools like Nyx-Net~\cite{schumilo2021nyxnet} and SnapFuzz~\cite{vanderveen2022snapfuzz} accelerate fuzzing via virtualization or library shims.
We share their goal of discovering protocol desynchronization and memory corruptions.
However, hypervisor snapshots require virtualization, and socket fuzzing incurs overhead.
We eliminate socket overhead via user-space in-memory mocks and tail slicing, reaching up to 53{,}732 executions per second.
